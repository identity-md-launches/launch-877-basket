# Website checks

Run from `web/` after the production build. `../artifacts/validation.md` is the actual final evidence and limitation record.

- `npm run validate`: ABI, decimal arithmetic, reason/error wording, inputs, encodings and live read-only verification.
- `node scripts/check-preservation.mjs`: protected files, current integration invariants, obsolete integration scan and file budget. This supersedes the obsolete call-expression equality check.
- `npx tsx scripts/run-browser.mjs`: bounded isolated Anvil fork plus Playwright browser. It creates only disposable fork fixtures, runs actual production UI sends against the original vault bytecode and records screenshots and decoded arguments. Requires an empty, unfinalized fork state, so it forks block 83,874,298 by default (vault 6 empty and not finalized, same code as today; the live vault is listed and may be finalized). It reads that block from the archive RPC `https://robinhood.api.pocket.network` through its own read-only proxy, which passes read methods only and retries busy reads. `BASKET_FORK_BLOCK` and `BASKET_RPC` override the block and the archive RPC; `SOLC` and `PLAYWRIGHT_MODULE` select local tools.
- `node scripts/inspect-export.mjs`: subpath export, all pages at four widths, fonts, overflow, keyboard and reduced-motion checks.
- `node scripts/check-guards.mjs`: injected account/chain/code/simulation failures; no transaction broadcast.

Playwright, Chromium and WebKit are external verification tools, not runtime dependencies. Install them outside the repository if absent and point `PLAYWRIGHT_MODULE` at Playwright's `index.mjs`. The 2026-10-09 pass used external Playwright with Chromium 156 and WebKit 27.2. The fork caches genuine account, vault and block-history system-contract reads before RPC pruning; it never patches vault storage or bytecode. Tests own their server/browser/fork lifecycle and close them on completion.

`Fixtures.sol` is test-only; it is not imported by the website and is never deployed to a public chain. Its sample symbols do not describe the live vault. No generated dependency/cache directory or state dump belongs in Git.

Design review uses the pinned Better Interface guide (Jakub Krehel, MIT) and Impeccable documentation method (Paul Bakaus, Apache-2.0). Both copyright notices and license texts are in `DESIGN-GUIDANCE-LICENSE`; review coverage and source locations are in the artifact report.

Additional checks: `npx tsx scripts/check-interface.ts` verifies line-numbered refusals, exact balances and pool/setting arithmetic; `node scripts/check-motion.mjs` checks scrolling geometry, repeated-strip coverage (since v10: each half its own endless Web Animation at the exact speed, no CSS animation, will-change or 3D, the window covered at loop phases around both resets, no `animationiteration` event across a real reset) and the Stock shelves' one-time swing (one iteration within 2 s, nothing moving afterwards or on scrolling back) in Linux Chromium at DPR 1/1.25/1.5. This is not native Windows display-scaling validation. The fork walkthrough covers 25 listing rows, decline/resume, an accelerated receipt timeout, pending transaction and reload, plus every transaction control. Screenshots wait for read/layout stability and use JPEG quality 32 (36 in v9 and v10, 40 before) to meet the submission budget.

`node scripts/check-calldata.mjs` compares the source with task-start Git source (HEAD). Since v11: every source outside Flows.tsx, wallet.tsx and main.tsx byte for byte, and those three once their listed v11 pieces are put back (the report records each piece by length and SHA-256). The rest does not depend on the pieces. The complete ordered added calls in Flows, wallet and main are pinned by full-expression hashes with readable ordered call names, outside the generated lists. Direct writes, aliases and mutating calls involving transaction state are compared with HEAD. Regenerating the pieces and attribute lists does not refresh those pins. wallet.tsx `send()`, Flows.tsx `approveAll()` and every `onSubmit` and `getSpec` equal HEAD word for word, and no attribute that builds or starts a transaction is added, removed or changed. In every source file the vault/token/feed/read calls, argument parsers, encoders, sends and reads on the public client equal HEAD in order and place, apart from two listed additions: the one added chain read (`client.getTransactionReceipt` of the visitor's own confirmed deposit, for the "You received" line, pinned with everything done with its answer) and the display-only `amount()` of the estimated total. Every wallet send, raw provider request and signing method, and every use of a listed name that reaches the network (fetch, XMLHttpRequest, WebSocket, EventSource, sendBeacon, importScripts, a dynamic import; written as a name, as a plain string or reached through `window[...]`), equals HEAD apart from one exactly pinned guard around the initial account reply, which ignores a reply superseded by a newer connection action or account event. The request itself is unchanged and no provider request is added. Disconnect only forgets the wallet on this page, makes no provider call and leaves the site's saved wallet permission for the visitor to manage in the wallet app. Its whole text is pinned; Vault, Scenery, main and Docs have no send or request. What a page can load or open without those names also equals HEAD in every file, with no exception: a picture, sound or worker made in script, the address bar, the history, the navigator, a new window, an element or HTML built in script, a `src`, `href`, `action` or `style` set in script, the JSX attributes that carry an address, a style or HTML, and attributes spread onto an element (the names are listed in the script); this is a list of known ways, not a proof that no other exists. The action attributes that differ from HEAD are listed one by one with a reason and hold no such call; every call of HEAD is kept apart from the listed calls of the old Deposit form; new uses of the state HEAD had and of the names that build, read or send are listed with their place; the names HEAD declares at the top of the three files and at the top of their components stay declared as they were; browser storage gains only the disconnected flag. Vault.tsx makes no read, check or send call, and its controls (the Stock shelves' included) and the shelves' handlers equal their pinned text; the Owner actions and the governance argument builders equal HEAD and the v9 refusal helpers equal their pinned text; HEAD's and the current encoders give the same calldata on the same inputs (deadline under fixed clocks), with no new refusal and the same refusal words. `node scripts/check-bundle.mjs` includes tracked lib files and all delivered assets in the 8 MiB budget and allows only the v11 file scope (Flows, wallet, main and styles; `web/public` unchanged, its `favicon.svg` and `dist/favicon.svg` still the chosen icon). Set `BASKET_SOURCE_ROOT` to the repository when running either from a disposable copy. Optional, new in v11: with `BASKET_GATE_FACTS=/absolute/file.json` set, `check-calldata.mjs` also writes the differences from HEAD it computed (attributes, guarded calls, calls and uses of watched names) to that file before it checks them against its lists; nothing is skipped or loosened by it. The file is read by the tool that generated the two lists between marker lines in the script (the tool is not part of this tree). Leave it unset for a normal run. `BASKET_BASELINE_DIST=/absolute/previous/dist node scripts/check-visibility.mjs` compares the six phone routes (375x812) with no wallet and a read-only owner connection; since v11 (against the v10 build) nothing may leave the first screen, so at that size the header with its new Disconnect button may not grow.
